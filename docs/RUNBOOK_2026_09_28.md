# Hướng dẫn vận hành thử nghiệm — 28/09/2026

## 1. Cấu hình riêng

Launcher đọc `.env`, `.env.local`, rồi `~/.config/buildappraisal/runtime.env`; biến của tiến trình được ưu tiên. Có thể đổi đường dẫn bằng `APPRAISAL_CONFIG_FILE`. Không đưa credential/backup vào Git.

Cloud cần APPRAISAL_DATABASE_URL bằng login riêng, APPRAISAL_DATABASE_CA, Supabase URL/anon key và profile người dùng. Login không superuser/BYPASSRLS; giữ TLS verify-full. DATABASE_URL/DIRECT_URL trong env quản trị được tách khỏi runtime.

`APPRAISAL_ENABLE_TEST_LOGIN=true` chỉ dùng staging + loopback với tài khoản thử nghiệm riêng. Tắt khi đưa ra ngoài môi trường thử nghiệm. File tài khoản riêng có quyền truy cập hạn chế; không sao chép mật khẩu vào tài liệu.

AI cần cấu hình đúng provider và model phía server; thiếu cấu hình vẫn chạy quy tắc và giữ trạng thái rõ. OCR cần TESSERACT_CMD và bộ ngôn ngữ vie+eng; hiện máy này chưa đạt readiness AI/OCR.

## 2. Khởi động

```powershell
pnpm check:runtime
pnpm dev
```

Chỉ chạy một terminal. Mở `http://localhost:8208/projects/appraisal`; Web và gateway API `/api/appraisal` cùng cổng 8208. Core 8201 và Worker 8200 chỉ lắng nghe loopback; readiness `/api/appraisal/readiness` cần đăng nhập. Cả ba cổng đọc từ `config/runtime-ports.json`. Launcher kiểm tra cổng, chờ Worker → Core → Web sẵn sàng; dịch vụ lỗi sẽ dừng các dịch vụ còn lại. Ctrl+C dừng cả bộ. `pnpm dev:appraisal` là alias, không chạy đồng thời với `pnpm dev`.

Nếu Windows báo EACCES, kiểm tra chỉ đọc:

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
netsh interface ipv6 show excludedportrange protocol=tcp
Get-NetTCPConnection -State Listen -LocalPort 8200,8201,8208 -ErrorAction SilentlyContinue
```

Cổng cũ 8000 thuộc dải Windows dành riêng 7972–8071. Người dùng đã yêu cầu chọn cổng mới; bộ cổng 8208/8201/8200 được kiểm tra và khởi động thành công ngày 28/09/2026. Nếu cổng bị chiếm, kiểm tra phiên dự án đang chạy; launcher báo lỗi và không tự đổi cổng hoặc dừng tiến trình lạ. Không chạy thêm `pnpm dev:web` khi bộ dịch vụ đang hoạt động.

Đã kiểm chứng qua trình duyệt: đăng nhập tài khoản thử nghiệm chuyên viên, tải 64 hồ sơ BCNCKT (50 dòng trang đầu) qua địa chỉ chung 8208.

## 3. Kiểm tra trước bàn giao

```powershell
pnpm lint:ui
pnpm typecheck:core
pnpm build
pnpm test:appraisal
python scripts/benchmark_appraisal.py
```

Unit test ép mode demo, bỏ cấu hình DB/model sống; không gọi model thật. Script cloud cần môi trường riêng và có thể tạo dữ liệu kiểm thử có dọn dẹp: đọc phần mô tả script trước khi chạy. Kết quả `check:runtime` chỉ in mode/tên biến thiếu/cổng, không in secret.

### Kiểm tra bổ sung sau đợt tối ưu G0–G6

```powershell
pnpm rules:check        # AGENTS/GEMINI/RULES.md khớp CLAUDE.md
pnpm typecheck          # TypeScript strict
pnpm test:web           # unit test frontend (node:test)
pnpm format:check       # prettier; Python: ruff format --check ai/app ai/tests scripts
```

- Dùng `127.0.0.1` thay cho `localhost` khi gọi API bằng script trên Windows, để tránh trễ ~2 s do thử IPv6 trước.
- Swagger nằm ở `/api/appraisal/docs`, chỉ bật ở môi trường demo/staging.
- Hạn xử lý (SLA) được tính lại mỗi lần lưu. Dữ liệu cũ dùng `python scripts/backfill_sla.py [--cloud] [--apply]`: mặc định chỉ chạy thử (dry-run); cloud sẽ chụp bản sao lưu trước khi ghi.

## 4. Migration và baseline

- DB hiện hữu: snapshot riêng trước thay đổi, đối chiếu ledger; dùng migration tăng dần. `verify_schema.py --apply <migration>` kiểm tra đường dẫn, rollback dry-run, rồi apply và ghi ledger.
- DB Supabase trống: dùng `supabase/baselines/20260928.sql`; tiền đề Auth/Storage và role chuẩn phải có sẵn. Không replay mọi migration lịch sử để dựng DB vì có migration mở anonymous.
- Kiểm thử PostgreSQL cách ly dùng `scripts/sql/supabase_test_prerequisites.sql`; đây là mô phỏng để kiểm tra DDL, không phải cài đặt Supabase hoàn chỉnh.
- `BASELINE_TEST_DATABASE_URL` phải chỉ vào loopback, tên DB bắt đầu `appraisal_baseline_test`, và DB trống. Chạy `python scripts/verify_baseline_local.py`.

CI có job PostgreSQL baseline và job chất lượng. Workflow đã được bổ sung trong repo; chưa có kết quả chạy từ xa.

## 5. Backup và phục hồi

Backup hiện tại nằm trong thư mục riêng `~/.config/buildappraisal/backups/`:

- Trước/sau đóng anonymous: metadata và manifest count/hash.
- `20260928-full-data-after-hardening`: metadata, 22 tệp dữ liệu public và manifest SHA-256; 1.818 dòng ở thời điểm chụp.

Phép thử phục hồi chỉ vào DB cách ly, sau baseline:

```powershell
python scripts/verify_restore_local.py <thu-muc-backup-rieng>
```

Script chỉ nhận URL loopback/tên DB kiểm thử; từ chối DB đã có dữ liệu nghiệp vụ. Kiểm tra SHA-256 file, schema từng hàng, đối soát record SQL, FK và sequence. Dùng Auth ID mô phỏng để kiểm tra FK; không khôi phục tài khoản/mật khẩu Auth hoặc bytes Storage.

Khôi phục toàn hệ thống cần backup Auth của Supabase, tệp Storage cùng hash/metadata, cấu hình riêng và diễn tập trên môi trường cách ly. Không rollback bằng cách mở lại anonymous. Kế hoạch phục hồi cloud phải xác định điểm khôi phục, tài khoản quản trị và đối soát scope trước khi đưa dịch vụ lên lại.

## 6. Dữ liệu demo

Fixture danh mục ở `ai/app/data/demo_catalog.json`, sinh từ dữ liệu mẫu trong repo; không có CCCD. Demo danh mục chỉ đọc. Hồ sơ vẫn lưu SQLite/bản gốc như trước.

`case_summaries` là projection đọc, trigger cập nhật cùng giao dịch insert/update/delete hồ sơ. Lần đầu mở DB cũ tự backfill và resolve chuỗi bổ sung; giữ nguyên payload/bản gốc. Nếu thay schema projection sau này, cần migration/version riêng và kiểm tra rollback/chuỗi lịch sử.

### Bộ dữ liệu mẫu theo luật (sample-v3)

Bộ mẫu được dựng bằng chính code workflow và SLA trên đồng hồ lùi ngày. Mỗi lần sửa nghiệp vụ phải dựng lại bộ mẫu.

- Dựng lại demo SQLite (sao lưu DB cũ ra `~/.config/buildappraisal/backups/` trước khi ghi):
  `python scripts/sample_dataset.py --fresh`
- Kết quả: 44 hồ sơ, 258 tệp, `output/appraisal/sample-dataset-v3.json` (kịch bản, trạng thái, căn cứ).
- Đẩy lên cloud staging (mặc định chạy thử; `--apply` chụp snapshot rồi mới ghi):
  `cd scripts && python publish_sample_dataset.py --staging --apply --replace`
  - Chỉ thay hồ sơ mô phỏng (`payload.sample = true`); hồ sơ thật giữ nguyên.
  - Không có `--replace` thì script chạy tiếp lần nạp bị ngắt (bỏ qua id đã có).
  - Tệp gốc cũ trên Storage không bị xóa.
- Danh mục dự án thay đổi thì chạy thêm `node --import tsx scripts/export_demo_catalog.ts`.

## 7. UAT còn cần thực hiện

1. Đăng nhập đủ bốn vai trò; đổi tài khoản không lẫn state/dữ liệu.
2. Tạo lần nộp, tải tài liệu, OCR, xác nhận trường, chạy quy tắc/AI, hủy và chạy lại.
3. Mở panel → mở modal con → nhập dữ liệu → backdrop/ESC; panel cha và dữ liệu chưa lưu phải được bảo vệ.
4. Bổ sung gallery → reload → tải ảnh gốc → hai cửa sổ sửa đồng thời phải báo CAS.
5. Sort/filter/resize/paging qua hơn 1.000 dòng; mở đúng UUID, xem lịch sử với tên rõ ràng.
6. Luồng GPXD và nghiệm thu từng subtype, phân công/chuyển trạng thái/SLA và rà soát lãnh đạo.
7. Xem/in PDF và render DOCX nhiều trang; chuyên viên đối chiếu biểu mẫu/căn cứ, chưa ký/phát hành.
8. Restart/lease/job cũ, mất quyền giữa chừng, mất DB và phục hồi tệp/bản ghi.

Tích hợp production, SMTP/domain, ký số/cấp số và dữ liệu chính thức vẫn theo giai đoạn sau trong kế hoạch đã duyệt.
